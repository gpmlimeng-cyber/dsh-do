# 群目标移植方案（网页端 → App 原生）

> 目标：把 ds-bot 网页端的群目标**原样**搬到 App，后端用现有网页端那套，界面用 App 已有组件。
> 不做：任务板、目标之外的新概念、我们之前自己设计的那套（全部作废）。

## 一、网页端到底是什么

### 胶囊（收起态）

一行，从左到右：

1. **状态标记**：完成时一颗勾，否则一个圆点（颜色随状态）。
2. **一句话 barLabel**，按状态变：
   - 起草中：「正在与你对齐目标」
   - 已停止：「已停止」
   - 已完成：「目标达成」
   - 暂停：「已暂停 · 这一段的名字」
   - 等你（idle）：「等你回复 · 这一段的名字」
   - 有当前段且没人跑：「最终检查」
   - 有当前段且任务都交了：「检查中 · 这一段的名字」
   - 其余：当前段标题
3. **分段条**：每段一格，四态——已过（绿）/ 当前（亮）/ 检查中 / 待做（灰）；暂停时当前格另一种颜色。
4. **成员头像**：当前这段任务涉及的成员，最多 4 个，多的写「+N」；正在干活的脉动。
5. **箭头**：点开/收起。

### 展开面板

- 顶部**阶段圆点**：一段一颗，已过的显示勾、其余显示编号，当前段高亮；点任意一颗切换查看。段特别多时（≥10）圆点收窄、放不下编号就只显示点。
- 中间**选中段**：
  - 段标题 + 「回到当前阶段」（当看的是别的段时出现）
  - 「做到什么算过：{验收}」
  - 打回信息（只在当前段、被打回过时）：「被 {管理员} 打回 {n} 次，上次说：{反馈}」
  - 「证据：{内容}」（只在已通过的段）
  - 任务列表：头像（干活时脉动、交了/完成了带勾、没开始变淡）+ 名字（成员自己的颜色）+ 这件事是什么
- **草稿态**：显示用户写的那段 brief。
- **无选中段**（目标已完成/停止）：显示 summary、evidence、停止原因。
- **目标与验收**（折叠区）：Objective / Done when / Rules（约束是列表）。
- **底部一行**：左边「目标与验收」折叠键；右边按钮——
  - 暂停（进行中）
  - 继续（暂停中）
  - 停止（进行中/暂停中，**点两下才生效**：第一下变「确定停止目标？」，3 秒内再点才停）
  - 清除（已完成/已停止）
  - 取消（起草中）
  - 「连正在做的事也停」（暂停中且还有成员在跑时）

### 起草表单

草稿阶段点开是一个输入框：「这个群要达成什么？」+「开始」。提交后是**给管理员发一句话**，由管理员在群里跟你对齐、再写成目标。

### 浮层

整个东西是「胶囊 + 挂在它下面的 pod」，点外面或 Esc 关闭。

## 一之补充：位置、两种显示模式与顶栏两态（2026-11-09 定）

胶囊不放输入框上方，放**群聊页顶栏**。做成设置项「群目标显示」：简单 / 完整。

### 收起态（collapsed）

| 模式 | 顶栏长什么样 |
|---|---|
| **简单**（默认） | 群名原样不动；右侧一颗**圆形进度环**，环内写 `3/4`，环色随状态 |
| **完整** | 群名收缩成一颗**圆形头像胶囊**（只显示群头像）；右侧是**完整目标胶囊**：目标图标 + 目标标题，**最右端是同一颗圆形进度环** |

### 展开态（expanded）

点目标胶囊 → 进展开态，三件事同时发生：

1. **目标胶囊横向铺满顶栏**：左边目标图标、中间目标标题、最右端是圆形进度环（`3/4`），环的右边是收起箭头。
2. **顶栏其他按钮全部隐藏**——抽屉、消息模式、模型选择、详情，一个都不留，只留目标这一颗。
3. **面板从胶囊下沿展开**，盖住消息区，一层淡遮罩压住后面的内容。

收起（点箭头 / 点遮罩 / 按返回键）→ 回到收起态，顶栏**恢复成进展开态之前的样子**：原来是简单模式就回简单模式，原来是完整就回完整。

### 为什么这么做

网页端这颗胶囊是「状态屏」，展开时它就是主角；App 顶栏本来就挤（五个按钮），展开时让它一个人占满，比塞在中间一块小地方清楚，也跟网页端的视觉权重一致。

## 二、现在的差距

### 数据（ds-bot 侧要补的字段）

现在的 `goal-view` 下发：

```
{ id, revision, status, title, objective, acceptance, constraints,
  current, stageCount,
  stages[{ title, acceptance, status,
           tasks[{ botId, bot, color, task, status, rework, feedback }] }] }
```

网页端还用到了这些，**目前没下发**：

| 字段 | 用在哪 |
|---|---|
| `brief` | 草稿态显示用户写的那段 |
| `summary`、`goal.evidence`、`reason` | 完成/停止时面板中间那段话 |
| `idle` | 胶囊写「等你回复」 |
| `stage.evidence` | 已过段的「证据」 |
| `stage.reworks` | 「被打回 N 次」 |
| `stage.feedback` | 「上次说：…」 |

成员头像还需要「这一群现在谁在跑」：`room-progress` 端点已有，App 直接取。

**动作**：`goal-view` 加 7 个字段（都是现成的数据，只是没下发），后端一处改。App 模型跟着加。

### 界面（App 侧要做的）

| 网页端 | App 用什么 |
|---|---|
| 胶囊 | `GlassSurface(tier: chrome)` + `DockRow`（输入框上方那条，和 todo 同一套壳），`DockSlot` 保证没目标时不占位 |
| 分段条 | 一排 6dp 小格，四种颜色 |
| 成员头像 | `BotAvatar`（`working: true` 会脉动） |
| 展开面板 | **`showAppSheet` 底部抽屉**（App 现有面板语言） |
| 阶段圆点 | 横向可滚的一排圆形按钮，同 `_StageBar` 的做法 |
| 任务行 | `ListPageRow` 换 `leading` 为头像 |
| 目标与验收 | `ListPageRow` 折叠区 |
| 底部按钮 | `TextButton` 一行，危险动作红色 |
| 起草表单 | `showAppSheet` 里一个多行输入框 + 发送 |
| 停止二次确认 | 第一次点击后按钮文案变「确定停止？」，3 秒复位 |

**一个刻意的差异**：网页端是浮层（挂在天上、可拖），App 上没有那个空间，用**底部抽屉**。这是 App 已有的面板语言（用量、权限、任务都用它），用户不用学第二套。

## 三、交互映射

| 场景 | 行为 |
|---|---|
| 群里没有目标 | 胶囊不出现（`DockSlot` 空高） |
| 有目标、收起 | 一行胶囊，点开抽屉 |
| 点阶段圆点 | 切换查看那一段（只读），当前段有「回到当前阶段」 |
| 暂停 / 继续 | 直接调 `goal-control` |
| 停止 | 两次点击，第二次才发 |
| 清除 | 已完成/已停止时出现，调 `goal-control` 的 `clear` |
| 起草 | 胶囊写「正在与你对齐目标」，点开是表单，提交后当一句话发给管理员 |
| 目标完成/停止 | 胶囊**继续显示**（网页端是这样，显示「目标达成」/「已停止」，可点开清除） |

> 注意：这一条跟上一版不同。上一版我们让完成的目标消失，网页端是留着的。

## 四、阶段

1. **ds-bot 补字段**（`goal-view` 加 7 个字段，`goal-control` 确认支持 clear/cancel）
2. **App 模型**（`DsBotGroupGoal` 加字段）
3. **胶囊重做**（barLabel / segments / faces 三件，跟网页端一样）
4. **面板重做**（阶段圆点 + 选中段 + 目标与验收 + 底部按钮）
5. **起草表单**
6. 静态检查 + 出包

## 五、验收

1. 没有目标时，输入框上方不占位。
2. 目标进行中：胶囊显示「当前段标题」+ 分段条（已过的绿）+ 当前段成员头像。
3. 点开：顶部阶段圆点，当前段高亮，正文是「做到什么算过」+ 任务列表（头像/名字/状态）。
4. 点别的段：能看到那段的验收和任务，出现「回到当前阶段」。
5. 暂停 → 胶囊变「已暂停 · 段名」，按钮变「继续」。
6. 停止：点一下变「确定停止？」，再点才停，胶囊变「已停止」。
7. 已完成：胶囊变成「目标达成」+ 勾；面板底部出现「清除」，点了目标消失。
8. 起草：胶囊「正在与你对齐目标」，点开是表单，提交后群里出现一条给管理员的消息。
9. 成员头像在有人干活时脉动，交了的带勾。
10. 目标与验收能展开，三块（Objective / Done when / Rules）都在。
