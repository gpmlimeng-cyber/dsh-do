## 2026-11-09 · 群聊顶栏与菜单

- **顶栏最右那颗改成 `⋯` 菜单**（现在它直接进「对话详情」`RoomAggregateDetailsPage`）。
  - 菜单顺序：`对话详情` → `消息范围` → `成员` → `搜索此群` → 分隔 → `清空会话`（红，最后）。
  - **群设置不进菜单**：群名胶囊已经进群设置（`RoomDetailsPage`），两处都叫「详情」会分不清。
  - **运行时与异常时让位**：有东西在跑，最右必须是「停止」；断线/权限异常必须是警示键。最重要的事不许躲进菜单。
  - 长按这颗键仍直接进对话详情，保留一键路径。

- **三条菜单规矩**（防止菜单变垃圾桶）：
  1. 只装「低频、可等、不常按」的；状态类和救命动作永远在面上。
  2. 进去的东西别处也得能到——只靠菜单才找得到的入口，等于藏起来。
  3. 顺序固定，不按频率自己重排；危险动作永远最后、红字。

- **菜单兼作插件插槽**（用户提的方向，未做）：手机端是 dsh-go 原生插件，**没有**「会话标题区入口」可映射，也没有「顶栏菜单」这种贡献点，要 App 侧新增。
  - 现成可复用的：`session.actions`（会话级动作，最多 2 条）、`panels`（插件页签）。
  - 建议形态：菜单固定项之后加一段插件分组，装 `session.actions`，再加一条「插件」入口进 `panels`。
  - 约束：插件项必须「一点就做」或「开面板」，**不许变成导航**；上限 2 条 + 一个插件入口；排序按 App 分组，不按插件声明顺序。
  - 插槽细节、字数上限、效果类型、wants 权限等已整理成 [plugin-surfaces.md](plugin-surfaces.md)。

## 2026-11-10 · 群内搜索与清空（架构师判断，未实现）

- **群内搜索**：要新开 Host 端点 `room/message-search {roomId, query, limit, cursor}`，返回 `{sessionId, seq, at, by, text}`，App 按 seq 跳。现有 `session/search` 每会话只出一条最佳命中、不返回位置，且 FTS5 索引默认关闭，解决不了「跳到群里那条」。**不做「只搜已加载」**，那是把不确定当确定。
- **清空会话**：不做真删。群消息真相在 `room.log` 预览与各 session 历史里，真删会毁掉成员上下文、目标/任务/审批的 seq 引用。要做就加 `room-clear {roomId, throughSeq}`：只清预览并在群数据里记 `clearedThroughSeq`，App 用这个截断点过滤旧消息。语义是「界面不再显示，底层保留」。
- 两条都**不碰现有契约**（`goal-control`、`session/search` 都不动）。
- 菜单里加「清空会话」时按 UI 危险项规则：单独分组、二次确认、文案写清后果、读屏念出后果。
