# 主页规划：四栏（会话 / 任务 / 发现 / 我的）

> 状态：2026-11-08 定稿方向，**先不做**。要动手时从这份开始。
> 模块编号 M1–M5，方便以后拆任务。

## 一、为什么是底部四栏

国内移动端 AI 产品清一色底部固定栏：豆包五格（对话/智能体/创作/云盘/我的）、元宝四格（问元宝/派/创作/我们）。它们有多个并行板块，需要并列；工具向产品（Kimi、ChatGPT、Claude）用侧栏，因为只有一个主流程。

我们除了会话，还有「我让它干的事到哪了」「有什么新东西能装进团队」「这台机器怎么配」。四格刚好。

## 二、横向规则

- 底部栏只在四个主屏出现；聊天页、详情页、群页隐藏。
- 每格记住自己的滚动位置。
- 任务格红点：有任务卡在「等前置」超过 3 天，或有今天的定时任务。
- 发现格红点：有新版本，或目录里有没看过的条目。
- 会话格保留现有抽屉（全部历史、置顶、分组），底部栏不替代抽屉。

## M1 底部栏壳

四格容器：图标 + 文字、选中态、切页保留各自的滚动位置、聊天页隐藏。一格一个 `Navigator`（切回来回到上次的位置，不重置）。

---

## M2 会话

**作用**：跟谁干活。

- 主屏保持现在的样子：Bot 单聊 + 群聊，置顶在前，按最近说话排。
- 顶部：搜索、新建。
- 未来：置顶分组、未读角标。
- 数据：现成的，不改。

不把「新建 Bot / 新建群」挪进来，它们留在侧栏新建面板。

---

## M3 任务

**作用**：我让它干的事，现在到哪了。

- 顶部三段筛选：**在办 / 等待 / 已结束**，默认在办。
  - 在办 = 进行中 + 已领取；等待 = 未开始（含等前置）；已结束 = 完成/失败/取消。
- 每条一行：群名 + 任务标题 + 状态 + 负责人 + 「等 3 号」。
- 点一行：跳到那个群，直接展开任务条并打开这条的面板。
- 下半块：**定时任务**（哪些 Bot 什么时候被叫醒）+ **群目标状态**（哪几个群在推进、第几段）。
- 数据：新增 `tasks-all`（跨群一次取）；定时任务和目标状态用现有接口。
- 一期只读；二期做勾完成、改派。

**依赖**：`tasks-all` 端点。

---

## M4 发现

**作用**：新东西、新能力、新鲜事、新朋友。

一页四块，从上到下。**社区不自建**：只做主流社区的汇集，内容在外部，我们只做浏览和跳转。

### M4.1 广场（做「装东西」）

- 智能体、连接器、插件、技能，能看能装。
- 本地已有的先列全；要有公共目录才叫「发现」。
- 数据：插件与 MCP 端点已有；需要**目录服务**（见下）。

### M4.2 圈子（做「找人和找 Bot」）

- 公开的 Bot / 智能体，看它能干什么，一键加成群成员或私聊。
- 跟广场共用同一份目录服务，只是视图不同。
- **前置**：账号体系。我们现在是「自带 key、引擎在本地」，没有「别人的 Bot」这个概念；要做得先有中心服务，这是从单机工具跨到平台的一步，单独决策。

### M4.3 头条（媒体源聚合）

- Agent / AI 相关的新闻、文章、视频。
- 源：RSS、公众号、YouTube 频道。
- 只读，不做推荐算法，按源分组、按时间排。

### M4.4 社区（主流社区汇集）

- 微博、X、HN、Reddit、V2EX、即刻这些地方的讨论，按主题汇集。
- **不自建 UGC**：不发帖、不评论、不点赞，点开跳原站。
- 与头条共用一套「源」模型，区别只是源类型（媒体源 / 讨论源）。

### 抓取与合规（M4.3 + M4.4 共用）

- **App 端不抓**。抓取放在只读聚合服务：定时抓、缓存、下发 JSON。理由：X、微博本地抓会撞墙和限流，缓存还能扛网络抖动。
- 源按「要不要授权」排：先免 key 的（Hacker News、Reddit、V2EX、GitHub、YouTube RSS），X 和微博要授权放后面。
- 合规三条写死：**只显示标题、摘要、来源、时间，点开跳原站**；不镜像全文、不搬运图片；每条带举报入口，能一键屏蔽某个源。

### 两个服务

| 服务 | 用途 | 给谁用 |
|---|---|---|
| 目录服务 | Bot / 智能体 / 连接器 / 插件 / 技能的清单 | 广场、圈子 |
| 聚合服务 | 外部内容源的定时抓取与缓存（只读） | 头条、社区 |

## M5 我的

**作用**：这台机器和这个团队怎么配。

- **设置**：主题、气泡、通知、默认模型。
- **用量**：token、花费，按模型 / 按 Bot 拆。
- **引擎与设备**：主机连接、引擎状态、诊断导出、更新。
- **账号与团队**：当前团队、切换主机、退出。

数据全是现成的，主要是**搬家**：把抽屉底部的设置组、侧栏的更新行挪进来。旧入口在抽屉里留一份，不做死。

## 分期

| 期 | 内容 | 关键依赖 |
|---|---|---|
| 一期 | M1 壳 + M2 会话（原样）+ M5 我的（搬家）+ M3 任务（只读汇总） | `tasks-all` |
| 二期 | M3 可操作（勾完成、改派）；定时任务进任务页 | 写接口按任务 id 定位群 |
| 三期 | M4.1 广场 + M4.3 头条（先三块现成的，再接几个免 key 源） | 目录服务（静态 JSON 起步）、聚合服务 |
| 四期 | M4.4 社区汇集 | 聚合服务加源 |
| 待决策 | M4.2 圈子 | 账号体系 + 目录服务；从工具跨到平台，单独拍 |

## 什么时候值得动

- 群数量 ≥ 3，或已经在多个群放任务 —— 「我总共欠几件事」才成为真问题。
- 广场那三块本来就有内容，不依赖群的数量，可以先行。

## 未决

- 任务格默认开「在办」还是「全部」。
- 「我的」里用量放最上还是最下。
- 群目标状态放任务格，还是单开一块。
- 发现四块的先后（广场 → 头条 → 社区 → 圈子 是我的建议；圈子最贵）。
- 目录服务和聚合服务放哪、谁运维（要有人管源列表和缓存）。
