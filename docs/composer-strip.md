# 输入框上方那一条：一条带子，三种人格

> 2026-11-09 讨论定稿。方向定了，未开工。

## 一、先给会话页的内容分四类

| 类 | 是什么 | 现在在哪 |
|---|---|---|
| **属性** | 这次对话「是什么」：群信息、基本设置 | 点群名/标题进去 |
| **对话过程** | 过程里长出来的东西：轨迹、改动、文件、上下文、任务进度 | 右上角按钮 |
| **输入** | 用户给的东西：文字、图片、文件、语音，**以及能挂上去的能力**（技能、插件、MCP、知识库、记忆） | 加号 |
| **动作** | 此刻要对正在发生的事做的决定：完成、取消、暂停、确认 | 输入框上方 |

关键判断：**能力不是另立一类，它就是「输入的上下文」**——挂一个技能和挂一个文件是一回事，都是给这次对话加料。所以技能、插件、MCP、知识库都归「输入」，都进加号。

由此：**独立的「插件行」取消。** 它原本是给插件硬塞的座位，位置从头就是错的。

## 二、一条带子，三种人格

输入框上方只有**一条**，按场景换内容，**高度和位置不变**（切换时不许上下跳）。

| 场景 | 人格 | 里面放什么 |
|---|---|---|
| 新建会话页 | **导航**：帮你快速开一件事 | 生图、创作、代码、写作、研究（按用过的排序，默认四个） |
| 会话空闲 | **快捷输入**：一点就挂上 | 模型短名、最近用的技能/知识库、拍照、文件 |
| 会话进行中 | **快捷操作**（就是活动行本身） | 左边：谁在跑、干什么、几步、计时；右边：完成、取消（失败时是重试） |

「进行中」不是另起一条，就是现在这条活动行——**左边状态，右边动作**，挤不下就点开看细节。

## 三、这一行里的东西必须「一点就做」

- 每颗是一次**动作**，不是一个入口：点「拍照」开相机，点「完成」就把任务完成，点「Flash」就换模型。
- 凡是「点开一个列表让你挑」的，都不在这一行（那是加号和「⋯」的事）。
- 三到五颗，按场景动态；固定不变的总有两颗永远用不上。
- **可配置**：默认给一套，长按能换（底层是 `ui.json` 的 `quickActions`，现在只是没暴露给用户）。

## 四、状态优先级

有东西在跑 → 「进行中」人格（活动行 + 动作）；
没在跑，在新建会话页 → 「导航」人格；
其余 → 「快捷输入」人格。

任何两个状态不许同时占这条带子。

## 五、加号的三层

1. **加素材**：相册、拍照、文件、语音；
2. **加能力**：技能、插件、MCP、知识库、记忆（选中的就是给这次对话挂上上下文）；
3. **起一件事**：AI 创作、写作、PPT、深度研究等模板。

## 七、溢出与「更多」（2026-11-09 补充定稿）

**不设上限，横向铺满一行；放不下的收进行尾一个图标按钮。**

- 胶囊个数不写死、**按屏幕宽度自适应**：先量出所有胶囊的总宽，装得下就全放，装不下就**逐步减一颗**，直到「剩下的 + 更多」放得下。
- **「更多」本身也占宽度**，所以要一起算；否则会出现「刚好铺满、但『更多』被挤出屏幕」。
- 「更多」是**图标按钮**（圆圈里一个「⋯」），跟胶囊齐平，不加文字——省出半颗胶囊的宽度。
- **只在溢出时出现**；没溢出就不画，不留空位。
- 挤出的一定是**最不常用的那几颗**（顺序：场景动作 → 固定的 → 按频率），不会随机换来换去。
- 屏宽变化（旋转、折叠屏展开）时**从「更多」里补位，不重排**。
- **极端兜底**：大字号或英文长名时可能连两颗都放不下，那就**只留一颗 + 更多**，不许出现半颗胶囊的残局。
- 点「更多」开动作面板（全部动作按频率排）；**长按**进编辑态，可以固定某项到前面，或收起前面某颗。
- **角标**：当「场景相关但没放进去」的动作（比如「完成」）被挤进「更多」时，图标上带一个小圆点——越重要的动作被挤进去，越要有提示，否则用户以为它不存在。

## 九、顶栏：群的仪表盘（2026-11-09 补定）

顶栏只回答三个问题：**这是哪个群、现在忙不忙、最近发生了什么。**
「在跑什么、几步、多久、能做什么」交给输入框上方那条，不重复。

结构：**一行身份 + 一行状态 + 三样信号**，不新增行。

- **身份**：群名（有目标时被目标胶囊替换，既定设计）。
- **状态行**：一行小字，回答「忙不忙」。
- **头像叠**：群名右边叠 1–3 个正在跑的成员头像，多的写「+N」——比写名字省地方。
- **已说 N**：说「说到哪了」，没有别的信息时它占主位。

**信号（按优先级）**

1. **在不在跑**：状态行的点——跑着是脉动主色，空闲是静态灰点。最优先。
2. **谁在跑**：头像叠。
3. **群记忆更新**：状态行短暂变成「记忆已更新 · 刚刚」，十秒后回落；右上角带小星标，点开进记忆页。
4. **异常**（断线、权限降级、额度不足）：状态行变警示色并直说。**这是唯一允许盖掉「在跑」的状态。**
5. **成员变动**：有人进群/退群时短暂显示一次「某某 加入」。

**两条硬规矩**

- 状态行**不超过 12 个字**，超了就用图标或头像代替——顶栏宽度固定，字多了群名没了。
- 同一时刻**只显示一条短暂提示**（记忆更新 / 成员变动 / 异常），排队显示，不叠。


## 十、会话页状态表（2026-11-09 群聊定稿，当晚评审后修订）

范围：**只群聊**。六份评审（产品、架构、UI、前端、后端、测试）意见已并入；
凡与代码冲突的，以代码为准，并在下面标出来。

### 10.1 四个位置，各说一件事

| 位置 | 说什么 | 代码落点 |
| --- | --- | --- |
| 顶栏 | **人群级**：这是哪个群、忙不忙、最近发生了什么 | `BotChatHeader.trailing` → `GoalBarProbe(roomId)`；状态行 `roomStatusOf` / `RoomStatus` |
| 输入框上方 | **个体级**：在跑什么、此刻能做什么 | `BotComposerDeck`：`LowBalanceBanner`、`SafeModeBanner`、`TodoDockSlot`、`GoalDockSlot`、`ActivityStripSlot`、`ComposerStripSlot`；`StripRiskChip` 是 dock 的 `accessory`，不是独立卡片；底部胶囊行是 `NativeComposerBar` |
| 输入区细节 | 用量、权限、说话 | 发送键旁上下文环（群总窗口）、麦克风、权限 chip |
| 消息流内 | 只说自己那一轮 | 思考行、工具行、`BotMemoryNoticeRow`、`GroupApprovalCard`、`BotQuestionCard` |

**高度预算（取代「最多两行」）**

- 输入框上方非输入区总高 **≤ 84dp**（2 × 36 + 2 × 6）；大字号 **≤ 96dp**。
  写成「两行」没法验收：dock 条 36、banner 40–44、chip 24–32，「两行」可以是 72 也可以是 106。
- 超预算时按 **异常／安全 ＞ 在跑 ＞ 目标 ＞ 快捷带** 砍；**异常类永远保留最后一条**。
- **键盘弹起**：消息区至少还要看到 3 行；不够时快捷带**临时收成一行**，不许压消息。
- 现状：deck 是 `Column(banner + DockStack(cards) + NativeComposerBar)`，**没有任何行数约束**；要落地得加优先级裁剪（前端估 20–30 行）。

**两条分工（防重复）**

- 顶栏只说人群级（几位在跑、忙不忙）；活动条只说个体级（谁在做什么）。
- **同一个人同一动作只在活动条出现**。现状顶栏写「正在讨论」、活动条写「某某 正在写」，同一件事说两遍，要改。
- 状态行上限**按渲染宽度判**（中英混排按字数会得出不同结论）；「12 字」只是中文经验值。

### 10.2 群目标只留在顶栏

- 修正：**群目标条已经不在 deck 里**（移到顶栏后被删掉），所以「不画目标卡」是**防回潮**，不是待办事项。
- 真正要删的是**待办卡** `TodoDockSlot`：群目标本身就是「目标 + 阶段 + 派活 + 验收」，`tasks` 就是「还差几步」。
- **陷阱**：`showSessionBars` 同时决定待办卡、目标卡**和权限 chip**（`autoApprove` / `preset` 都读它，`bot_composer_deck.dart` 102–103 行）。直接置 `false` 会让群里的权限入口一起消失——要拆成 `sessionBars` 与 `permissionChip` 两个开关（deck 约 10 行，群页 1 行）。
- **目标胶囊回落**：完成后保留 **10 秒**再让回群名；**清除后立即**回落。不定的话两个实现一定不一样。

### 10.3 目标按钮：与网页端一一对齐

网页端 `src/client/goal.js` 的 `bt-goal-foot` 就这几颗：

| 目标状态 | 按钮 | 动作 |
| --- | --- | --- |
| 起草中 `drafting` | 取消 | `goal-control clear` |
| 进行中 `active` | 暂停、停止 | `pause` / `stop` |
| 已暂停 `paused` | 恢复、停止；有人在跑多一颗「连当前工作一起停」 | `resume` / `stop` / **`stop-room-work`** |
| 已完成、已停止 | 清除 | `clear` |

- **「连当前工作一起停」不走 `goal-control`**：Host 只在 `pause` 分支读 `stopWork`，而且要求 `active`；已暂停时再 `pause` 会被 `wrongState` 拒掉。网页端这颗按钮也是直接调 `stopRoomWork`（`client/goal.js` 180/221 行）。App 侧端点现成：`dsbot_api.dart` 的 `stopRoomWork`。
- `stopWork: true` 只用于「**从 active 暂停并顺手停掉当前工作**」这一种。
- `stop` 动作 Host 内部已无条件 `rt.stopRoomWork(room.id)`，所以「停目标」天然连带停全群工作。
- `clear` 白名单：active / paused 拒；drafting 删；complete / stopped 归档。
- 推进权：`pass` / `rework` 只存在于管理员 Bot 的 `group_goal` 工具里，`goal-control` 只有四个动作——**没有「通过本阶段」按钮**，所以快捷带不做「完成」，要做就 `@管理员`。
- **`bot/stale`**（`goalId` 过期）：刷新 `goal-view` 并重开面板，不能只弹一句错。
- 四个动作各有状态白名单，非法迁移直接拒——**状态机闭合，契约不改**。

### 10.4 快捷带运行态：两颗纯图标

- 只有两颗：**停止**（`AppIcons.stop`）、**暂停**（`AppIcons.pause`），**不带文字**。另有 `paused` 圆版，不要混用。
- **位置：停止在左，暂停在右**（右端留给可逆的那个），两键间隔 8。
- **尺寸**：视觉 24；**触控区等于胶囊高（36 / 44）**，用命中区外扩，不撑高布局。「视觉 24 / 触控 48 / 与胶囊等高」三者不可能同时成立，按这条走。
- **两段式**：停止第一次点，图标变实心红，同时**在快捷带左端**写「再点一次停止」，**提示 3 秒 / 有效 3 秒**，两边一致；
  - 现状 App 是提示 **2 秒**、可点 **3 秒**（`group_goal.dart` 的 `_stop`），第 2–3 秒提示没了还能触发停止，必须改成 3/3。
  - 不浮层、不额外占高（浮在停止键上方会盖住活动条或输入框上沿）。
- **红色只给停止**，整条带子别处不许用 danger 色。
- **删文字不等于删标签**：读屏念「暂停目标」「停止目标」「停止目标，再点一次确认」。
- 「连当前工作一起停」**不进带子**，只在面板里（已暂停且有人在跑）。
- **这是新增实现，不是「照抄网页端」**：App 里没有 `STOP_ARM_MS`、没有这套两段式（约 30–40 行）。

### 10.5 停止的语义：按目标 × 有没有人在跑 分派

| 目标 | 有人在跑 | 停止 = |
| --- | --- | --- |
| `active` | 是 / 否 | `goal-control stop`（Host 内部连带 `stop-room-work`） |
| `paused` | 是 | **只停工作**：`stop-room-work`，目标保持 `paused` |
| `paused` / 无目标 | 否 | **不出现停止键**（没东西可停，出现就是空按钮） |
| 无目标 | 是 | **`stop-room-work`**（全群真停） |
| 无目标 | 否 | 不出现 |

- **不能用 `client.cancel(room.sessionId)` 冒充全停**：它只取消群回合那条 relay session，成员各自的工作照跑，界面却以为停了。群里现在的「停止」就是这么做的，要改。
- 「停某一位」只在活动行 / 成员行（那里用 `stop-member-work`），带子上不做。
- **暂停不打断**正在跑的成员（只改目标状态）：面板要有一行说明或提示，否则用户点完看见成员还在动，会以为没生效。
- **断线时**两颗图标置灰并给一句话；「点了没反应」不许出现。

### 10.6 默认与记账（2026-11-09 定）

- **空闲态固定 4 颗**：**模型**（必在，没配置时显示占位、点进配置）、**拍照/附件**、**@成员**、**第 4 颗按本地频率选**（没有数据时用语音）。
- **只有第 4 颗是动态位**，前三颗位置永远不动——否则用一下按钮就换位，用户记不住位置。
- 宽度不够时**从第 4 颗开始**收进「更多」，**前三颗永远可见**。
- **频率只记本地**：界面偏好不进 Host，换手机丢了可接受。
- **频率怎么算**：按使用**次数**排，次数相同看**最近一次**；不做时间衰减。
- **长按固定的候选**：**全部可用动作**（不是只常用），按上一条的频率排。
- **新建会话页的导航点下去**：**新建一个会话并预填提示词**，不是跳到某个模板会话。

## 十一、消息范围（2026-11-09 定）

群聊的「消息模式」从三档收到两档：**全部** 与 **只看某位成员**。

- 「仅与我相关」删掉。它靠「从我的消息开始、直到有人被 @」去猜，日志里没有 `replyTo` / `round`；猜错的后果是该看的话被藏起来，比没有过滤更坏。老数据里的 `relevant` 读到 `all`，不会一升级就空白。
- 入口不再常驻顶栏。过滤状态型、低频，不配一颗常驻键；入口放在 **详情面板里的「消息范围」** 和 **成员行**（本轮只删旧键，两个入口随后接上）。
- **过滤生效才有标记**：顶栏一颗「只看 某某 ×」，点 `×` 回全部；不过滤时零占位，宽度还给群名。
- **不跨启动记住**：模式只留内存，跨启动回「全部」。第二天进来只看到某一位，会让人以为群没动静。
