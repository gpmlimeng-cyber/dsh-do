# 输入框上方那一条：一条带子，三种人格

> 2026-11-09 讨论定稿。方向定了，未开工。

## 一、先给会话页的内容分四类

| 类 | 是什么 | 现在在哪 |
|---|---|---|
| **属性** | 这次对话「是什么」：群信息、基本设置 | 点群名/标题进去 |
| **对话过程** | 过程里长出来的东西：轨迹、改动、文件、上下文、任务进度 | 右上角按钮 |
| **输入** | 用户给的东西：文字、图片、文件、语音，**以及能挂上去的能力**（技能、插件、MCP、知识库、记忆） | 加号 |
| **动作** | 此刻要对正在发生的事做的决定：完成、取消、暂停、确认 | 输入框上方 |

关键判断：**能力不是另立一类，它就是「输入的上下文」**——挂一个技能和挂一个文件是一回事，都是给这次对话加料。所以技能、插件、MCP、知识库都归「输入」，都进加号。

由此：**独立的「插件行」取消。** 它原本是给插件硬塞的座位，位置从头就是错的。

## 二、一条带子，三种人格

输入框上方只有**一条**，按场景换内容，**高度和位置不变**（切换时不许上下跳）。

| 场景 | 人格 | 里面放什么 |
|---|---|---|
| 新建会话页 | **导航**：帮你快速开一件事 | 生图、创作、代码、写作、研究（按用过的排序，默认四个） |
| 会话空闲 | **快捷输入**：一点就挂上 | 模型短名、最近用的技能/知识库、拍照、文件 |
| 会话进行中 | **快捷操作**（就是活动行本身） | 左边：谁在跑、干什么、几步、计时；右边：完成、取消（失败时是重试） |

「进行中」不是另起一条，就是现在这条活动行——**左边状态，右边动作**，挤不下就点开看细节。

## 三、这一行里的东西必须「一点就做」

- 每颗是一次**动作**，不是一个入口：点「拍照」开相机，点「完成」就把任务完成，点「Flash」就换模型。
- 凡是「点开一个列表让你挑」的，都不在这一行（那是加号和「⋯」的事）。
- 三到五颗，按场景动态；固定不变的总有两颗永远用不上。
- **可配置**：默认给一套，长按能换（底层是 `ui.json` 的 `quickActions`，现在只是没暴露给用户）。

## 四、状态优先级

有东西在跑 → 「进行中」人格（活动行 + 动作）；
没在跑，在新建会话页 → 「导航」人格；
其余 → 「快捷输入」人格。

任何两个状态不许同时占这条带子。

## 五、加号的三层

1. **加素材**：相册、拍照、文件、语音；
2. **加能力**：技能、插件、MCP、知识库、记忆（选中的就是给这次对话挂上上下文）；
3. **起一件事**：AI 创作、写作、PPT、深度研究等模板。

## 七、溢出与「更多」（2026-11-09 补充定稿）

**不设上限，横向铺满一行；放不下的收进行尾一个图标按钮。**

- 胶囊个数不写死、**按屏幕宽度自适应**：先量出所有胶囊的总宽，装得下就全放，装不下就**逐步减一颗**，直到「剩下的 + 更多」放得下。
- **「更多」本身也占宽度**，所以要一起算；否则会出现「刚好铺满、但『更多』被挤出屏幕」。
- 「更多」是**图标按钮**（圆圈里一个「⋯」），跟胶囊齐平，不加文字——省出半颗胶囊的宽度。
- **只在溢出时出现**；没溢出就不画，不留空位。
- 挤出的一定是**最不常用的那几颗**（顺序：场景动作 → 固定的 → 按频率），不会随机换来换去。
- 屏宽变化（旋转、折叠屏展开）时**从「更多」里补位，不重排**。
- **极端兜底**：大字号或英文长名时可能连两颗都放不下，那就**只留一颗 + 更多**，不许出现半颗胶囊的残局。
- 点「更多」开动作面板（全部动作按频率排）；**长按**进编辑态，可以固定某项到前面，或收起前面某颗。
- **角标**：当「场景相关但没放进去」的动作（比如「完成」）被挤进「更多」时，图标上带一个小圆点——越重要的动作被挤进去，越要有提示，否则用户以为它不存在。

## 八、还没定的，以及要谨防的

**设计漏洞（先定）**

1. **条数会挤爆**：群聊输入框上方现在可能同时有活动行、目标条、任务条，再加快捷带就是第四条。要给一条铁律——**同一时刻最多两条**，超出合并或收起。
2. **动作的权限**：群目标的「完成/取消」用户不能直接做（只有管理员能推进）。用户点它实际是**发一句话给管理员**，走消息，不是本地改状态。不定清会做成「点了没反应」。
3. **危险动作二次确认**：「完成」可以一下点掉；**「取消」「停止」必须点两下**（跟目标面板一致），快捷带上误触代价太大。
4. **新建会话页的导航点下去做什么**：是「新建会话并预填提示词」，还是「切到那个模板的会话」？两种体验差很远，未定。

**实现细节**

5. **乐观更新**：点「完成」当场变状态，不等服务端；失败回滚并提示，否则用户会连点。
6. **频率记在哪**：本地还是引擎？换手机要不要带过去——影响「按频率排」能不能成立。
7. **键盘弹起时**：快捷带留着（打字时最想点的就是拍照、@成员这类），不收起。
8. **读屏与大字**：读屏要念出「快捷带，当前进行中，完成、取消」，否则视障用户用不了；大字号下按实测宽度重算。

## 九、顶栏：群的仪表盘（2026-11-09 补定）

顶栏只回答三个问题：**这是哪个群、现在忙不忙、最近发生了什么。**
「在跑什么、几步、多久、能做什么」交给输入框上方那条，不重复。

结构：**一行身份 + 一行状态 + 三样信号**，不新增行。

- **身份**：群名（有目标时被目标胶囊替换，既定设计）。
- **状态行**：一行小字，回答「忙不忙」。
- **头像叠**：群名右边叠 1–3 个正在跑的成员头像，多的写「+N」——比写名字省地方。
- **已说 N**：说「说到哪了」，没有别的信息时它占主位。

**信号（按优先级）**

1. **在不在跑**：状态行的点——跑着是脉动主色，空闲是静态灰点。最优先。
2. **谁在跑**：头像叠。
3. **群记忆更新**：状态行短暂变成「记忆已更新 · 刚刚」，十秒后回落；右上角带小星标，点开进记忆页。
4. **异常**（断线、权限降级、额度不足）：状态行变警示色并直说。**这是唯一允许盖掉「在跑」的状态。**
5. **成员变动**：有人进群/退群时短暂显示一次「某某 加入」。

**两条硬规矩**

- 状态行**不超过 12 个字**，超了就用图标或头像代替——顶栏宽度固定，字多了群名没了。
- 同一时刻**只显示一条短暂提示**（记忆更新 / 成员变动 / 异常），排队显示，不叠。
